# 知识库周期治理说明

## 目标

周期治理负责持续发现知识库变化，并把变化转为可审核、可追溯的知识更新草稿。它不直接覆盖正式知识条目，只有人工批准后才发布。

## 处理链

```text
01_原始资料库
    ↓ SHA-256 增量扫描
新增 / 修改 / 未变化 / 删除 / 重复
    ↓
10_待审核更新（pending 草稿）
    ↓ 人工审核
approved
    ↓ 原文哈希再次校验
02_分类台账、03_管理要点、08_事件分析、04_记忆卡片
```

## 目录和状态

| 目录 | 用途 |
|---|---|
| `00_系统说明/知识治理索引.json` | 保存路径、哈希、版本、状态和审核时间 |
| `09_周期汇总` | 更新日志、周报、月报 |
| `10_待审核更新` | 自动生成但未发布的草稿 |
| `11_重复与冲突` | 内容重复和来源版本变化记录 |
| `12_失效资料` | 被删除或来源失效的资料记录 |

常见状态：`new`、`changed`、`draft_pending`、`published`、`removed`、`stale`、`failed`。

## 任务入口

```powershell
pythonw knowledge_job.py daily
pythonw knowledge_job.py weekly
pythonw knowledge_job.py monthly
pythonw knowledge_job.py publish
```

桌面端“系统设置 → 知识库周期治理”也可以立即执行这些任务，并安装或移除 Windows 计划任务。

## 发布保护

草稿保存原始文件路径和内容哈希。发布前会检查：

1. 草稿状态必须为 `approved`；
2. 来源文件必须存在；
3. 当前来源文件哈希必须与审核时一致。

任一条件不满足，发布会跳过该草稿并记录日志。这样可以避免审核旧版本、发布新版本造成内容错配。
